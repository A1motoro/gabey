# C 的 L2 闭环制动仿真

在 A 的 12 个 CA 切入场景上，C 的仿真器分别接入 Reactive、CV、CA、CTRV 和 Oracle。每个场景另跑一次始终巡航的对照，共 72 次。对照中 6 个场景发生碰撞，6 个安全通过。五个制动系统均避开了前 6 个场景的碰撞，也都在后 6 个场景中全程巡航。这里的分母仅覆盖 A 的固定合成网格。

## 实验设置

- 场景来自 `ca_scenario_set()`。初始纵向中心距取 20、30 m，本车相对旁车的初始纵向速度取 0、2 m/s，切入车纵向加速度取 −2、0、+2 m/s²。旁车在 0.5 s 开始换道，3 s 内完成，同一窗口内施加给定纵向加速度，之后维持末速度。
- 每个系统都调用 `run_sim`。Reactive 使用 P 的车道内纵向评估器，CV、CA、CTRV 和 Oracle 分别通过 `make_system` 接入同一个 `PredictiveAssessor`。普通预测器用当前及过去的观测，Oracle 通过绑定场景读取旁车未来位置。Oracle 的自车仍由同一策略闭环控制。
- 所有系统从 15 m/s 开始，遵循 [L2 基线规范](l2-baseline.md)中的滞回制动、定向矩形和 C 的复现配置。
- 为覆盖末帧的 Oracle 查询，让同一个 A 场景生成器提供到 19 s 的轨迹。所有系统的评分窗口仍为 0–15 s。真实碰撞按两车实际运动计算，各系统的 TTC 只用于决定刹车。
- 以同场景无制动对照在 15 s 内是否碰撞划分危险和良性场景。良性场景中出现制动指令即记为一次有误刹的场景。制动次数按进入 BRAKE 状态的次数统计。最近中心距和制动统计截止于首次接触或仿真结束。本节数字用的就是这个 15 s 窗口。全组于 2026-11-24 同意的比较口径是 15 s 决策、19 s 结果，用于 D 的 exp02 / exp03 / exp05；这 12 个场景在该口径下仍是 6 个危险、6 个良性。

## 结果

| 系统 | 危险场景碰撞数 / 6 | 良性场景误刹数 / 6 | 制动次数合计 |
|---|---:|---:|---:|
| 无制动对照 | 6 | 0 | 0 |
| Reactive | 0 | 0 | 23 |
| CV | 0 | 0 | 23 |
| CA | 0 | 0 | 18 |
| CTRV | 0 | 0 | 25 |
| Oracle | 0 | 0 | 23 |

4 个减速切入场景在无制动时全部碰撞。4 个匀速切入场景中，初始相对速度为 2 m/s 的两例发生碰撞。4 个加速切入场景在无制动时全部通过。

## 复现与交接

在仓库根目录运行以下命令。脚本可通过 `--output-dir` 指定输出位置。

```bash
python experiments/c_l2_closed_loop.py
```

默认目录为 `outputs/logs/c_l2_closed_loop/`。

- `runs.csv` 每行是一组场景和系统，含场景参数、制动设置、反事实标签、首次制动、首次接触、最近中心距、制动次数和持续时间。`min_center_dist_m` 对应 `SimLog.min_dist_until_contact`，`first_contact_s` 对应 `SimLog.first_collision_t`。未发生事件的时间留空。
- `timeline.csv` 每行对应一个 0.1 s 状态，共 10,872 行。可用 `case_id` 和 `system` 与结果表关联。TTC 为 `inf` 表示该步没有有限冲突估计。末行没有执行动作。无制动对照首次接触以后的状态标有 `after_contact`，仅反映仿真器继续积分。
- `decelerating_cut_in.png` 展示初始中心距 20 m、相对速度 2 m/s、切入车纵向加速度 −2 m/s² 的速度与 TTC 时间线。该例无制动时约在 3.37 s 首次接触。图中圆点为各系统首次刹车，叉号为无制动对照首次接触。TTC 图仅展示 0–6 s 范围内的有限值。
