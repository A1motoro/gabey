# C-T6 兜底机制：四个设计问题与仿真验收

本文记录 C-T6 进入实现前的设计讨论。前三项是建议方案，第四项沿用讨论中认可的滞回行为。下列场景是待执行的验收用例，时间参数以当前仿真控制周期 `dt = 0.10 s` 为背景。

## 1. 预测器和 Reactive 能否并行？50 ms 到了由谁决定？

**建议让两条通道并行，给整帧设置一个截止时间。** 参考实现逐目标同步调用预测器，返回后才检查耗时。假设同一帧有三辆车，每辆预测耗时 40 ms，三次调用分别都低于 50 ms，累计却达到 120 ms。若预测器卡住，控制侧还会一直等下去。

每帧开始时固定观测快照和帧号，把本帧目标交给独立的预测工作进程，控制侧同时运行 Reactive。预测器可按帧批量处理目标。到本帧 50 ms 截止点，控制侧只读取已就绪且帧号匹配的结果，逐目标作决定：

- 两条通道均有效时，取参与风险评估通道的最小 TTC（预计碰撞时间）。
- 只有一条有效且观测足够新鲜时，使用该通道，记录来源。
- 两条都无可信结果时，保留该目标风险未知的状态，按第 2 节处理。

Reactive 也要纳入整帧预算。若要求在截止点发出控制命令，调度器必须能按时取走已就绪结果，任何工作进程都不能阻塞它。迟到结果按帧号丢弃；预测进程仍忙时跳过过时任务，避免积压。

**验收**　用可控时钟模拟 Reactive 在第 8 ms 完成、预测在第 80 ms 完成。第 50 ms 应能用 Reactive 发出本帧决定，第 80 ms 的旧结果也不能覆盖下一帧。另测多个目标共享预算、预测任务一直未完成两种情况。真实模型接入后再测端到端耗时。

## 2. 两条通道都缺少有效观测，要等多久才刹车？

**每帧继续尝试获取观测，同时根据最后可信的制动状态行动。** 两条通道共享车辆历史和自车路径，切换算法无法补回同时缺失的输入。应显式传递“观测缺失或过期”。有效观测下算出的 `TTC = +∞` 表示未发现冲突，两种情况会触发不同的控制动作。

| 失联前的状态 | 首个缺测周期 | 缺测持续时 |
|---|---|---|
| 已在软刹或硬刹 | 保留原档位，继续建立所需制动力 | 继续制动，接近停车时沿用 L3 的平滑停车逻辑 |
| 正在巡航或恢复加速，最近有效观测无近迫风险 | 把目标加速度设为零，平滑撤去驱动力，同时等待下一次观测 | 可先试缺测满 0.20 s 后进入软刹，逐渐减速至停 |
| 有风险的前车失联，其他目标仍可见 | 保留前车对应的制动要求，继续评估可见目标 | 其他目标要求更强制动时立即升级；其正常观测不能解除前车触发的制动 |

从最后一个可信观测的**采样时间戳**计算观测年龄。重复收到旧样本不能清零计时。重新观测到危险时，当帧允许加强制动；准备松刹时，可先要求连续两帧新鲜有效观测，并满足原有滞回退出条件。两帧恢复和 0.20 s 宽限都是待标定的仿真参数。这里假定执行端仍能取得自车速度并执行控制命令。

**验收**　在同一组合成切入和无危险场景上，对比 0.10、0.20、0.30 s 三档宽限，记录碰撞、最小间距、误刹和速度损失。另测旧时间戳重发、仅前车失联、危险目标重新出现，确认这些事件各自触发预期动作。

## 3. 丢帧时怎样保持制动，又遵守 jerk 限制？

**Hold 决定制动档位，L3 统一计算实际加速度。** 应在仿真控制入口显式注入本帧决策缺失，让正常帧、缺测帧和恢复帧共用同一个 `prev_a`（上一帧实际执行的加速度）、jerk 限幅和速度边界。制动档位表示想施加多强的制动；若直接复制上一帧加速度，可能把制动力冻结在刚开始建立的水平。

| 丢帧时刻 | 预期的加速度变化 |
|---|---|
| 刚进入硬刹，实际加速度为 −2 m/s² | 保持硬刹，继续趋向目标 −6 m/s²。远离停车边界时，按硬刹 jerk 20 m/s³，每 0.10 s 可从 −2 走到 −4，再到 −6 |
| 正在恢复，实际加速度为 +1.5 m/s² | 将目标改为零。按舒适 jerk 5 m/s³，每步变化最多 0.5 m/s²；若目标保持为零，依次执行 +1.0、+0.5、0。若其间升级为软刹，则从当时的实际值继续过渡 |

**验收**　从仿真的实际加速度序列计算逐帧 jerk，即相邻两帧加速度之差除以 `dt`。分别覆盖进入缺测、连续缺测、恢复观测和接近停车四处边界；检查所用档位的 jerk 上限、硬刹制动力是否继续建立，以及停车后的速度。

## 4. 延迟裕度可以既提前刹车又延后松刹吗？

**可以。本次讨论接受这一行为。** 对有效且有限的 TTC 做统一补偿，再送入原有状态机：

`TTC_eff = max(0, TTC_raw − latency_margin)`

以 `latency_margin = 0.20 s` 为例，原始 TTC 对应的切换条件如下。等于退出阈值时仍保持该档位。

| 档位 | 进入条件 | 满足退出该档位的条件 |
|---|---|---|
| 软刹 | 原始 TTC < 3.2 s（原 3.0 s） | 原始 TTC > 3.7 s（原 3.5 s） |
| 硬刹 | 原始 TTC < 1.7 s（原 1.5 s） | 原始 TTC > 2.2 s（原 2.0 s） |

两档滞回带宽均保持 0.5 s。硬刹优先，退出硬刹后仍可能处于软刹。延迟裕度用于补偿**已有的有效 TTC**；第 2 节的宽限决定**缺测持续多久后开始软刹**。即使实验都取 0.20 s，也要分别配置和调参。

**验收**　让 TTC 先下降再上升，记录实际进入帧和退出帧，并覆盖恰好等于阈值的情况。将裕度设为零时应复现现有 L3 的切换序列；正无穷保持正无穷，缺测状态继续走失效策略。
