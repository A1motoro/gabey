# 项目选定加码方案：白盒 2D 激光雷达感知栈与防后车追尾博弈

> **文档定位**：本文件记录经物理第一性原理推演与源码核对后，最终敲定的**两个项目加码（Extension）方向**——向上游补齐 **白盒 2D 激光雷达感知与跟踪模块（`pbs.perception`）**，向下游延伸 **防后车追尾纵向安全博弈评估**。文档已剔除未采用方案（如脱离 2D 底座的相机/YOLO 识别、离线点云外接、多车型静态权重、横向打方向变道）及早期讨论中的物理与源码误区。

---

## 0. 核心主线与全栈闭环升级逻辑

本项目的核心研究问题是（见 [spec.md §0](spec.md)）：

> **“在控制其他条件不变的前提下，引入轨迹预测（以及预测不确定度）能把 AEB 纵向紧急刹车的安全工作区扩大多少？预测误差与误报的代价又在哪里？”**

在完成 L1–L3 主线后，将本文件的两个选定加码接入系统，即可在不破坏现有冻结契约（`pbs.types` 与 400+ 项回归测试）的前提下，把原本“开天眼读真值轨迹 + 只管前车不管后车”的局部实验，打通为一条完整的**自动驾驶纵向安全全栈闭环**：

```text
实时 2D 激光射线点云 → 聚类 + L-Shape 框拟合 + 卡尔曼跟踪 (加码一: pbs.perception)
    ↓ 输出带真实物理伪影与滤波滞后的观测轨迹 Trajectory
运动学 / 神经网络预测 + 不确定度包络膨胀 TTC (主线核心: pbs.prediction + pbs.risk)
    ↓ 争取切入预警提前量 (Lead Time)
L2 二值急刹 vs L3 三级温和预制动 StagedBrakingPolicy (主线控制: pbs.sim)
    ↓ 导出闭环自车轨迹 SimLog
前向防撞 + 后车反应延迟跟驰防追尾双向评估 (加码二: Rear-End Sandwich Analysis)
```

## 加码方向一：白盒 2D 激光雷达感知栈（`pbs.perception`）

### 1. 为什么选“实时白盒 2D LiDAR 管线”？（第一性原理排雷）

为了替代当前仿真中“开天眼”直读上帝真值轨迹的做法，我们从物理与架构第一性原理出发排除了以下三条走不通的路线，确立了最终方案：

1. **为什么不用相机 / YOLO 视觉方案？**
   本项目是纯 2D 鸟瞰（BEV）几何仿真，既无摄像头 RGB 图像数据，也无三维车高与路面俯仰渲染，强接视觉模型或目标分类属于无源之水。而激光雷达在 2D 平面上天然等价于**极坐标射线投射（Ray-casting）与定向矩形车身（OBB）边缘采样**，与现有 `5.0 m × 2.0 m / 2.5 m` 碰撞几何 100% 同构。
2. **为什么不直接下载 Waymo Perception 原始点云？**
   Waymo Perception 数据集虽然公开提供了完整 20 秒的原始激光雷达点云（注：当前仓库接入的 WOMD 运动数据集仅含前 1.1 秒历史点云，不含未来帧点云），但离线录制的真实点云在闭环 AEB 仿真中存在两大结构性死结：
   - **闭环视角错位（Viewpoint Shift）**：在闭环仿真中，自车（`ego`）一旦因预测到风险而提前刹车，后续时刻自车的真实坐标已落后于当年采集车（SDC）录制点云时的历史位置，距离、方位角与遮挡阴影关系全部改变，静态点云无法重渲染新视角画面；
   - **合成主基准断层**：项目核心交付物（96 / 255 参数化合成场景网格与 Failure Boundary）由数学公式生成，不存在对应的真实点云文件。
   此外，外接重型 3D 点云深度学习框架（如 `spconv` / PointPillars）会破坏课程要求的轻量化单机 Python 环境一键复现准则。
3. **为什么不做“读真值框再手动加假漂移公式”的伪观测模型？**
   直接读取真值坐标后人为叠加经验偏置，既非真正的感知模块，又极易把几何漂移方向写反。构建**真正不偷看真值框标签的白盒点云处理链路（点云生成 → 聚类 → L-Shape 拟合 → 卡尔曼跟踪）**，才能让所有传感器物理缺陷从几何定律中**自然涌现（Emergent）**。

### 2. 正确的物理几何机制（修正早期遮挡与框漂移误区）

在白盒 2D 激光雷达感知下，传感器物理特性会自然产生三类专杀简单运动学预测器的真实伪影：

1. **正确的遮挡几何：邻道遮挡盲区（而非本车道前车遮挡）**
   - **场景前提**：现有合成 `cut_in` 场景（[`scenarios.py`](../src/pbs/data/scenarios.py)）中全场仅有 1 辆切入车，无遮挡物；评估遮挡效应时，需专门构造含第 2 辆遮挡车的场景（如双车 `occluded_cut_in` 或路侧停车遮挡的 `occluded_crossing`）。
   - **车道关系纠偏**：在切入场景中，挡住 `ego` 视线的**绝不是与 `ego` 同车道的近处前车**（否则被加塞的是前车而非 `ego`，除非前车突然变道闪开的 Cut-out 场景），而是**相邻车道中排在切入车后方的大车/慢车**——`ego` 本车道前方净空，相邻车道后方慢车斜向挡住前方小车视线，小车突然从邻道慢车车头前探头并入 `ego` 车道（机动版“鬼探头”）。
2. **局部点云与 L-Shape 观测框中心漂移（Box-Center Drift）的正反双向效应**
   当激光束只能扫到目标车局部边缘（单边或一角）时，基于可见点云拟合的矩形框中心会偏离真实车辆质心，且在**入盲区**与**出盲区**时方向截然相反：
   - **进入半遮挡 → 框中心向本车道内侧跳变 → 诱导邻道直行“幽灵误刹（False Brake）”**：
     相邻车道一辆**正常直行（真实横向速度 $v_y = 0$，绝不切入）**的车辆，原本整车尾部/侧面可见（观测中心在邻道中心 $\pm 3.5\text{ m}$）；当其外侧半边车身滑入后车视线阴影、仅剩靠近本车道的内侧边缘能反射激光点时，可见点云中心会在 $0.1\sim 0.3\text{ s}$ 内迅速向本车道方向跳变约 $0.5\sim 0.9\text{ m}$。这会**无中生有地制造出一个朝向本车道的虚假横向切入速度**，极易诱导 `CV / CA` 等预测器误判切入而触发幽灵误刹。
   - **刚从盲区露头切入 → 框中心向外侧回缩 → 掩盖真实切入速度导致“晚刹（Late Brake）”**：
     当真正的切入车刚从邻道遮挡车前方探出内侧前角时，首帧激光仅扫到最靠近本车道的内侧角；随着随后几帧车体逐渐完整显露，拟合框中心反而向邻道外侧的真实质心“回缩”。这一**反向漂移会短暂抵消一部分真实的横向切入速度**，并叠加盲区导致的历史帧缺失，推迟简单预测器发现冲突的时刻。
3. **远距角分辨率稀疏与跟踪滤波滞后（Sparsity & Tracker Phase Lag）**
   - 在固定角分辨率（如 $\Delta\theta = 0.5^\circ\sim 1.0^\circ$）与测距噪声下，远距离目标车仅能反射寥寥数个激光点，导致单帧 L-Shape 航向角与框尺寸估计抖动；
   - 多目标卡尔曼滤波器（KF）虽能平滑单帧抖动并估算速度，但强滤波会引入**速度/加速度相位滞后（Phase Lag）**，直接与预测器的提前量（Lead Time）形成工程权衡。

### 3. 模块架构与源码无损接入方案

#### 3.1 核查现有源码约束（避坑说明）
当前 [`src/pbs/sim/simulator.py`](../src/pbs/sim/simulator.py) 第 200–204 行的 `ObservationModel.observe(history, *, t_now)` 接口存在两项严格限制：
1. 仅接收单车独立 `history`，拿不到自车当前闭环坐标 `(ego_xy, ego_heading)` 及场上其他遮挡车辆的位置；
2. 硬性校验 `np.array_equal(history.t, reference_t)` 且要求 `history` 非空——若直接把遮挡帧从 `history.t` 中剔除，会当场触发 `ValueError` 或 `MissingObservationError`。

#### 3.2 落地方案（纯 NumPy 零外部依赖，100% 向后兼容）
新建独立包 `src/pbs/perception/`，包含四层白盒流水线：
1. **`Lidar2DSensor`（2D 射线采样器）**：以自车实时位姿 `(ego_xy, ego_heading)` 为原点发射 $N$ 束激光（如 360 束，最大量程 `80 m`，含测距高斯噪声 $\sigma_r$），与场上所有车辆真实 OBB 四条线段求最近交点，输出无标签 2D 点云坐标数组 `(M, 2)`（自动体现视线遮挡与远距稀疏）。
2. **`cluster_points` + `fit_lshape_boxes`（点云聚类与 L-Shape 矩形框拟合）**：仅输入原始点云 `(M, 2)`，按欧氏距离阈值分簇后，用经典搜索式最小方差/面积准则拟合定向矩形观测框 `(center_x, center_y, length, width, heading)`（点数过少时退化为点簇质心）。
3. **`MultiObjectKalmanTracker`（多目标关联与卡尔曼跟踪）**：使用匈牙利算法 / 最近邻门限关联帧间检测框，维护状态向量 $[x, y, v_x, v_y]$ 的卡尔曼滤波器，实时组装出每条活跃航迹的因果历史 `Trajectory`（并可选导出位置协方差供不确定度感知评估使用）。
4. **`run_sim` 可选感知钩子**：保持原 `observation_model` 参数与现有全部单测一字不动，在 `run_sim(...)` 新增可选关键字参数 `perception_model: PerceptionPipeline | None = None`。当启用 `perception_model` 时，每步将 `(t_now, ego_xy, ego_heading, current_agent_states)` 喂入感知栈，仅对感知栈已检出并建轨的 `Trajectory` 调用 `assessor.assess(ctx, track_history)`（全盲区未检出目标天然不触发评估，真值碰撞判定仍严格使用上帝真实轨迹）。

## 加码方向二：防后车追尾纵向安全博弈（Rear-End Sandwich）

### 1. 核心动机与物理故事
在前车急刹或旁车近距离切入场景中，真实的量产 AEB 不仅要避免撞上前车，还要防止因自身过晚、过猛地“一脚死刹（`-6.0 m/s²`）”导致后方人类驾驶员反应不及而追尾自车。
> **架构边界红线**：严格遵守 [spec.md §1.2](spec.md) **不做横向变道（Steering）** 的规定，不改动一维路径弧长仿真器底座，专注于**纵向前后三车耦合安全博弈**。

这一方向能够把 **P 模块的“预测提前量（Lead Time）”** 与 **C 模块 L3 的“三级温和制动（`StagedBrakingPolicy`）”** 串成极具说服力的因果链：
- **Reactive + 二值急刹**：等切入车压入本车道才看见，剩余距离极短，只能瞬间踩满 `-6.0 m/s²` 紧急死刹 → 即使勉强没撞上前车，后方存在人类反应延迟的后车也极易追尾自车；
- **Predictive + 二值急刹**：虽提前发现了切入，但一触发就是 `-6.0 m/s²` 满制动，后车追尾风险依然偏高；
- **Predictive（`CV / CTRV / NN-UA`）+ L3 三级温和制动（`StagedBrakingPolicy`）**：利用 2D 预测争取到的 `0.5~1.1 s` 提前量，在 `1.5 s ≤ TTC < 3.0 s` 阶段先以 **`-2.5 m/s²` 温和预减速（配合 Jerk 限幅）** 平滑拉开前向车距，同时相当于提前点亮刹车灯为后车争取宝贵的反应缓冲时间，实现**“前向不撞、后向不被撞”的双赢**。

### 2. 零侵入落地方案（后处理耦合仿真）
完全无需修改 `src/pbs/sim/simulator.py` 核心循环，直接在评估/实验层实现独立的后车跟驰耦合仿真函数 `simulate_following_vehicle(sim_log, ...)`：
1. **输入**：直接消费任意系统跑出的闭环日志 `SimLog`（含每步 `t, ego_x, ego_y, ego_v, ego_a, action`）。
2. **后车物理模型（带反应延迟的 IDM / 比例制动跟驰模型）**：
   - 初始时刻（$t=0$），后车位于自车正后方初始车距 $d_{\text{rear}, 0}$（如扫描 `10~25 m` 网格），初速度与自车相同；
   - 后车驾驶员存在反应延迟 $\tau_{\text{rear}}$（如 `0.8~1.2 s`）：感知到的自车状态为 $(x_{\text{ego}}(t - \tau_{\text{rear}}), v_{\text{ego}}(t - \tau_{\text{rear}}))$（或自车制动灯亮起 $\tau_{\text{rear}}$ 秒后才开始全力制动），最大制动减速度受限于路面附着极限 $a_{\text{rear, max}} = 6.0\text{ m/s}^2$。
3. **核心产出图表**：
   - 在切入场景集上统计各系统的 **双向事故分解图（前向碰撞率 vs 后向被追尾率 vs 双向完全安全率）**；
   - 绘制在 $(d_{\text{rear}, 0}, \tau_{\text{rear}})$ 平面上的**后车安全跟驰边界图**，直观量化“预测提前量 + 分级温和制动”把后方安全区域扩大了多少。

## 总结：两大选定加码的协同分工与交付对照

| 维度 | 加码一：白盒 2D LiDAR 点云感知栈 (`pbs.perception`) | 加码二：防后车追尾纵向博弈 (`Rear-End Sandwich`) |
| :--- | :--- | :--- |
| **解决的核心痛点** | 消除上游“开天眼直读真值轨迹”假设，检验各预测器在真实几何遮挡、L-Shape 框漂移与跟踪滞后下的鲁棒性 | 消除下游“只顾前向死刹不顾后车”的单车局限，证明“预测提前量 + L3 温和制动”的真实交通流安全价值 |
| **核心技术模块** | 2D 射线求交点云 → 欧氏聚类 → L-Shape 矩形拟合 → 卡尔曼多目标跟踪 | 基于 `SimLog` 的带反应延迟 $\tau_{\text{rear}}$ 后车跟驰动力学积分与双向碰撞判定 |
| **新增/配合场景** | 1. 现有标准网格 + Waymo 场景（测点云稀疏与滤波滞后）<br>2. 新增双车场景：`邻道遮挡切入`（测晚刹）与`邻道直行半遮挡`（测框内漂幽灵误刹） | 直接复用现有 `cut_in` / `lead_brake` 闭环仿真产出的 `SimLog`，扫描后车初始车距与反应时间 |
| **外部依赖与环境风险** | **零外部依赖**（纯 NumPy + SciPy/内置匹配，课程标准环境一键运行） | **零外部依赖**（纯 NumPy 后处理脚本，不动仿真器一行底层代码） |
| **对现有测试的影响** | `run_sim` 默认 `perception_model=None`，现有 400+ 测试 **100% 零回归** | 独立消费 `SimLog`，对 `src/pbs/` 核心契约 **零侵入** |
