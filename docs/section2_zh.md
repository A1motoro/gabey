**风险估计与 AEB.** 前向碰撞预警的性能要求已有标准 [1]，自动紧急制动则主要靠场景化的测试协议来评估 [2]。这两类做法里，决策变量本质上都是纵向的碰撞时间（TTC），或者由距离与距离变化率在匀速假设下推出的"所需减速度"。更形式化的一路做法，则把这个阈值换成一个可证明安全的最小跟车距离，即责任敏感安全模型（RSS）[3]。我们从中借三样东西：把 TTC 作为基线控制器的决策规则；把"最后一刻"的刹停距离 `d = v·t_react + v²/(2a)` 当作解析参照，用来检查仿真得到的失效边界是否离谱；以及"把系统的运行极限写成一块区域，而不是一个聚合数字"这个表达习惯。控制器本身我们刻意保持为单一 TTC 阈值——这样系统之间测出来的差异，才能归因于"冲突被怎么看见"，而不是归因于一个更复杂的决策规则。

**运动预测.** 短时程预测通常分成两派：运动学模型与学习型模型 [4]。运动学模型——匀速（CV）、匀加速（CA）、恒定转率与速度（CTRV）[5]——是绝大多数跟踪与预测模块里可解释的基线；学习型序列模型，如 Social LSTM [6] 与 Trajectron++ [7]，能显著降低位移误差，代价是要训练数据、训练时间，以及把模型接进闭环的工程量。我们的预测层只做运动学模型。这是一个范围决定，而不是对当前最优方法的判断：学习型预测器一定强于匀速，而它在我们这个比较里会落在匀速与 oracle 之间。正因为如此，我们必须保留一个 oracle 层——它给出"任何预测器最多能贡献多少"的上界；而 oracle 与 CV 之间的差距，就是用"碰撞结果"而不是 ADE 来计价的预测误差代价。场景生成采用最小抖动（五次多项式）横向剖面 [8]，并对峰值横向加速度设上限，保证生成的切入场景在动力学上可行。

**数据与评测.** nuScenes [9]、highD [10] 等公开数据集提供了带地图信息的真实轨迹，也提供了高速换道与切入的运动学参照。预测误差在真值已知的**解析样例**上度量——一条直线场景用于正确性，一段最小抖动切入用于体现匀速模型固有的误差——因此 ADE/FDE 的结论不依赖仿真器本身。课程提供的样例片段用于验证数据读取，并作为扩展，提供一段真实纵向冲突的案例研究。该片段里确实存在一次冲突，但没有任何一次切入本车道的换道，因此我们的**切入基准是合成的**。它的合理性由上面的运动学边界、以及对横向加速度上限的敏感性分析来论证，而不是由真实切入统计来校准——这个限制我们在第 4 节明写，不隐藏。评测上我们报**相图**，即（初始间距，相对速度）平面上的碰撞/不碰撞分界，而不是一个聚合分数，因为这条分界的位置与形状才是研究对象。

**我们的定位.** 在我们读到的两类文献里，这两条线通常是分开评估的：预测一侧报 ADE/FDE，AEB 一侧报碰撞与误刹结果 [2,4]。我们把两者接进同一个闭环（在普通笔记本上就能跑）：预测器在一个统一接口之后可替换，同一场景既能用"车道门控"的 reactive 基线回放，也能用预测式系统回放。在这个直接比较之外，一个扩展会把收益拆成两部分——"车道门控"的贡献与外推的贡献（§3.5），这样"预测有帮助"才成为一个可归因的结论，而不是一个被观察到的现象。代价一侧，误刹用反事实方式计价（§4），使收益与代价在同一批场景上衡量。

## B. 哪些地方**不需要**引文（别为了凑数硬引）

| 正文位置 | 为什么不用引 | 正文里应改成什么 |
| --- | --- | --- |
| "我们报相图而不报聚合分数" | 这是**方法论选择**，不是事实主张 | 保留理由句（"因为分界的位置与形状才是研究对象"），不挂编号 |
| "我们保留 oracle 层" | 同上，是我们实验设计的一部分 | 已有理由句（"它给出任何预测器最多能贡献多少的上界"），不挂编号 |
| "误刹用反事实方式定义" | 同上；而且我们没有声称"已有工作这样做" | 指向 §4 的显式定义，不挂编号 |
| `d = v·t_react + v²/(2a)` | 高中/大一运动学，属常识 | 直接写公式，不引 |
| `interfaces.md`、`constant.py` 等仓库文件 | **不是学术引用** | 放第 3 节末尾一句"Implementation: `src/pbs/...`"，不要写成 `(constant.py)` 这种括号引用 |

> 一条原则：**能自己说清理由的，就别引**。引文只承担"这个说法在世界上存在过"的举证责任。乱引反而会被追问"这篇具体说了什么"。
